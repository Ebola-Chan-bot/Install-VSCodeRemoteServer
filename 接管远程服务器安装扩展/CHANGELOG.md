本文件记录「接管远程服务器安装」扩展的版本变更，版本号遵循语义化版本。

# 1.0.0

- 首个版本：总开关「安装VSCode远程服务.接管远程服务器安装」+ 主机清单设置「安装VSCode远程服务.接管的主机」+ 命令「选择要接管的主机…」（多选列表实时扫描 `~/.ssh/config`，勾选保存即生效）；接管范围由用户逐主机勾选，未勾选主机保持 Remote-SSH 自带安装。
- 开启后勾选主机在 Remote-SSH 每次连接前由 Install-VSCodeRemoteServer 模块安装远程服务器，替换 Remote-SSH 自带的安装步骤。
- 主机接管前已配置外部 preconnect 脚本时不自动套壳：弹窗让用户选择「直接覆盖（原脚本引用丢弃，不可恢复）」或「复制一行调用代码到剪贴板、自行粘贴进原脚本」；后者钩子配置一概不动，还原时扩展同样不做任何事、只提示手动删除那一行。
- 关闭后摘掉指向本扩展的钩子条目并删除生成脚本，Remote-SSH 恢复自带安装。
- 接管文件拆为三层（均在全局存储目录）：每主机一份薄脚本（只含主机名与一行调用，逐字节稳定、是参与 Remote-SSH 授权哈希的唯一文件）、一份公共实现（从扩展目录原样复制）、一份配置（模块路径与发布通道），日后改进逻辑不会重新弹授权窗。
- 免密登录探测失败时直接报错并以非零退出码中止本次连接，不再静默回退 Remote-SSH 自带安装（preconnect 的标准输入是 `ignore`，无法交互收密码，回退只会掩盖问题）。
- 输出改为按秒批量刷出、经标准输出字节流整块写出：日志无多余空行、无被拆断的行。
- 原生组件补丁改为先按官方同款两步补丁验证用 node（先 RPATH 后解释器规避 patchelf#524 损坏缺陷；临时副本上验证通过才原子替换），首次接管即完成 `*.node` 补丁、不再延后一轮。
- 新增「启用保活的主机」设置与两步勾选命令「选择接管与保活的主机…」：服务保活逐主机可选（与接管独立可重叠）；启用保活的主机每次连接 preconnect 自动检修保活包装（幂等部署/升级/自愈），VS Code 更新到新提交号后下一次连接自动补上，无需手动重跑保活命令。
# 1.0.1

- 修复并发连接/重连时 Remote-SSH 报 `CodeError(AuthChallengeBadToken)` 连接失败的问题。根因之一是接管安装脚本每次运行都无条件 `pkill` 命令行含提交号的进程，把上次会话正在服务的 VS Code Server 与 command-shell daemon 一并打死（提交号就嵌在它们的路径里），重连与多开窗口互相残杀；现改为仅在确有产物需要重装时才清理旧进程。
- 服务保活包装脚本升级为 WRAPPER-V6-SINGLE-DAEMON：同提交号只保留一个 command-shell daemon，端口通告改由包装脚本写入各自会话的日志，无论并发安装会话读到哪份日志内容端口值都完全一致，端口↔令牌错配不复存在。鉴权相应降级为仅 vsda 签名挑战（CLI 官方无令牌模式），令牌不再作为第二道防线。
- 保活占位进程改为 5 分钟后自动退出，不再随每次连接永久堆积。
- 修复 comm 改名器从未落位的部署链路缺口：此前占位符漏替换导致改名器模板一直“未提供”，VS Code 服务的 node 进程树（comm=MainThread）持续被主机周期回收误杀重启；现随批上传并落位，服务进程树自动改名为回收豁免名。
- 竞速等待输出不再显示本地侧上传字节（本地下载阶段恒为 0，易被误读为卡死），只报远程侧下载进度；远程侧无下载能力时直接说明等待本地供给。
- 本地下载进度与竞速等待的报告节奏统一为自适应：进度不足 2/3 时每周期加 1 秒、超过 2/3 后每周期减 1 秒（下限 1 秒），不再固定每 30 秒一条，数秒内决出的竞速也能看到等待心跳。
