本文件记录「接管远程服务器安装」扩展的版本变更，版本号遵循语义化版本。

# 1.0.0

- 首个版本：总开关「安装VSCode远程服务.接管远程服务器安装」+ 主机清单设置「安装VSCode远程服务.接管的主机」+ 命令「选择要接管的主机…」（多选列表实时扫描 `~/.ssh/config`，勾选保存即生效）；接管范围由用户逐主机勾选，未勾选主机保持 Remote-SSH 自带安装。
- 开启后勾选主机在 Remote-SSH 每次连接前由 Install-VSCodeRemoteServer 模块安装远程服务器，替换 Remote-SSH 自带的安装步骤。
- 主机接管前已配置外部 preconnect 脚本时不自动套壳：弹窗让用户选择「直接覆盖（原脚本引用丢弃，不可恢复）」或「复制一行调用代码到剪贴板、自行粘贴进原脚本」；后者钩子配置一概不动，还原时扩展同样不做任何事、只提示手动删除那一行。
- 关闭后摘掉指向本扩展的钩子条目并删除生成脚本，Remote-SSH 恢复自带安装。
- 接管文件拆为三层（均在全局存储目录）：每主机一份薄脚本（只含主机名与一行调用，逐字节稳定、是参与 Remote-SSH 授权哈希的唯一文件）、一份公共实现（从扩展目录原样复制）、一份配置（模块路径与发布通道），日后改进逻辑不会重新弹授权窗。
- 免密登录探测失败时直接报错并以非零退出码中止本次连接，不再静默回退 Remote-SSH 自带安装（preconnect 的标准输入是 `ignore`，无法交互收密码，回退只会掩盖问题）。
- 输出改为按秒批量刷出、经标准输出字节流整块写出：日志无多余空行、无被拆断的行。
- 原生组件补丁改为先按官方同款两步补丁验证用 node（先 RPATH 后解释器规避 patchelf#524 损坏缺陷；临时副本上验证通过才原子替换），首次接管即完成 `*.node` 补丁、不再延后一轮。
- 新增「启用保活的主机」设置与两步勾选命令「选择接管与保活的主机…」：服务保活逐主机可选（与接管独立可重叠）；启用保活的主机每次连接 preconnect 自动检修保活包装（幂等部署/升级/自愈），VS Code 更新到新提交号后下一次连接自动补上，无需手动重跑保活命令。
# 1.0.1

- 修复并发连接/重连时 Remote-SSH 报 `CodeError(AuthChallengeBadToken)` 连接失败的问题。根因之一是接管安装脚本每次运行都无条件 `pkill` 命令行含提交号的进程，把上次会话正在服务的 VS Code Server 与 command-shell daemon 一并打死（提交号就嵌在它们的路径里），重连与多开窗口互相残杀；现改为仅在确有产物需要重装时才清理旧进程。
- 服务保活包装脚本升级为 WRAPPER-V6-SINGLE-DAEMON：同提交号只保留一个 command-shell daemon，端口通告改由包装脚本写入各自会话的日志，无论并发安装会话读到哪份日志内容端口值都完全一致，端口↔令牌错配不复存在。鉴权相应降级为仅 vsda 签名挑战（CLI 官方无令牌模式），令牌不再作为第二道防线。
- 保活占位进程改为 5 分钟后自动退出，不再随每次连接永久堆积。
- 修复 comm 改名器从未落位的部署链路缺口：此前占位符漏替换导致改名器模板一直“未提供”，VS Code 服务的 node 进程树（comm=MainThread）持续被主机周期回收误杀重启；现随批上传并落位，服务进程树自动改名为回收豁免名。
- 竞速等待输出不再显示本地侧上传字节（本地下载阶段恒为 0，易被误读为卡死），只报远程侧下载进度；远程侧无下载能力时直接说明等待本地供给。
- 本地下载进度的报告节奏改为自适应：汇报间隔按预计剩余时间自动疏密（估算的剩余时间不足以把间隔逐级收回 1 秒时开始收紧，否则继续放宽），下载快慢不同都能恰好在收尾处收到 1 秒一条，不再固定在 2/3 进度处切换，也不再固定每 30 秒一条；竞速等待心跳无总大小可比对，间隔只增不减，数秒内决出的竞速也能看到等待心跳。
- 修复 Windows 远程单会话安装在竞速模式下报 `Cannot find path ...\AUTO\REMOTE_CLI.zip` 中断安装的问题：竞速暂存目录此前以相对路径参与远端各环节，随执行上下文漂移（实测后台下载作业的起点是「文档」目录），与本地上传的落点对不上；现统一解析到登录目录下的数据目录。
- 恢复 Windows 竞速的本地供给启动：远端清建暂存目录后输出供给触发标记，本地供给听到标记才启动、先清理后上传；竞速前清空上一轮残留的残包与标记，不再因残留完成标记误判本地供给已获胜。
- 修复 Windows 远程主机 Remote-SSH 连接必超时的问题（Connecting with SSH timed out，超时调到 122 秒仍失败）：Remote-SSH 把连接脚本经 stdin 管道喂给远端交互式 PowerShell REPL 执行，回显与提示符让输出膨胀（约 8KB）并滞留在管道渲染段，而脚本收尾是常驻观察循环不再产出输出，握手标记永远到不了连接端；接管安装现在会幂等部署「管道执行守卫」（用户 profile，仅对无命令行参数的管道会话生效），把整本脚本转为非交互执行，输出降到约 1.5KB 一次冲刷即达，实测握手 7.4 秒到达。
- 本地供给（本地下载/上传）的进度与日志随产生实时输出，不再积压到收尾统一打印，竞速过程中可实时看到本地侧进行到哪一步。
- 修复进度显示滞后于实际发生的问题：远端安静时段（解包等）最后一段输出不再滞留到下一行到达才上屏（实测竞速决出晚十余秒才显示），显示时刻与实际发生时刻一致。
- 修复守卫自身的致命缺陷（表现为 Windows 远程主机随机连不上、Connecting with SSH timed out，且与超时时长无关）：旧守卫要读完 stdin 收尾（EOF）才执行脚本，而终端场景下管道 EOF 经常不来，实测追踪只有 GUARD_START 没有 STDIN_BYTES、脚本永久不跑。守卫改为分块即读即执行：逐行累积、语法能解析就立即执行，完全不依赖 EOF；实测把管道收尾压后 25 秒，握手仍在 8.1 秒到达（旧守卫则永久挂死）。部署逻辑带版本识别，旧守卫块自动剥离后换新。
- 窗口连接超时后残留的死安装终端进程树由下一次接管连接自动清理：Remote-SSH 在隐藏终端跑安装脚本，超时放弃后终端的 pty 宿主先死、cmd 连带内层 cmd/ssh 子树成为孤儿挂在死管道上（仍占控制台会话、仍握着已放弃的远程隧道），残留累积会拖垮后续连接的输出投递。清理特征 = 命令行带 `vscode-linux-multi-line-command` 且 8 代祖先链内无存活 `OpenConsole`/`conhost` 宿主，整树 `taskkill /T`；存活安装终端（宿主在侧）与活动连接一概不碰。
- Remote-SSH 安装命令在窗口终端里根本未执行（连接终端空白、ssh 进程未启动、反复超时）时，扩展自动检测并弹出通知：该形态是 VS Code 窗口终端服务的上游缺陷，状态在窗口进程内部，重载无效、扩展无法进程内重建，唯一有效恢复是新窗口重开。检测特征 = 近 20 分钟 Remote-SSH 日志中同名接管主机 ≥2 次连接超时且无网络/凭据层报错；通知提供「在新窗口打开…」（按 `ssh-remote+<hex>` authority 一键开新窗口）与「关闭本窗口」两个动作，30 分钟节流一次。
