把 Install-VSCodeRemoteServer 模块接入 Remote-SSH：一个开关决定远程服务器由谁安装。开关开启时，Remote-SSH 每次连接前都由本模块安装远程服务器（本地下载+上传与远程自下载竞速、旧 glibc 自动部署官方 sysroot、CLI 引导预装），Remote-SSH 自带的安装步骤检测到服务端已就位便直接复用；开关关闭时一切还原为 Remote-SSH 自带安装。

# 功能特性

- **只有一个开关**：设置项「安装VSCode远程服务.接管远程服务器安装」，无需任何其它配置
- **开启即替换**：接管后远程服务器一律由本模块安装，Remote-SSH 自带安装步骤不再产出任何东西
- **关闭即还原**：把 `remote.SSH.preconnect` 恢复为接管前的取值、删除本扩展生成的接管脚本，Remote-SSH 恢复自带安装
- **接管范围自动确定**：`~/.ssh/config`（含 `Include` 展开）里的全部主机；接管前已配置过 preconnect 的主机也一并覆盖
- **链式兼容**：某主机接管前已有的 preconnect 脚本会在本模块安装完成后原样执行，既有行为不受影响
- **绝不阻断连接**：接管脚本出错只写日志不中止连接；未配置免密登录的主机自动跳过接管、保持 Remote-SSH 自带安装

# 使用方法

1. 在扩展设置里勾选「接管远程服务器安装」（等价于在 settings.json 写入 `"安装VSCode远程服务.接管远程服务器安装": true`）。
2. 之后每次 Remote-SSH 连接都会先经本模块安装远程服务器。首次连接时 VS Code 会弹一次 preconnect 脚本授权确认，选「Allow and Don't Ask Again」即可。
3. 取消勾选即还原为 Remote-SSH 自带安装。

# 工作原理

Remote-SSH 提供 `remote.SSH.preconnect` 设置：连接发起前在本机执行一个脚本（Windows 上必须是 `.ps1`，以 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File` 调用、**不带任何参数、不注入环境变量、标准输入是 ignore**，脚本运行时无法得知自己被哪台主机触发；非零退出会中止连接）。本扩展开启接管后，把该设置指向按主机生成的接管脚本，脚本调用本模块的 `安装-VSCode远程服务` 先把远程服务器装好；Remote-SSH 自带安装步骤随后发现服务端已就位便直接复用——安装由此被本模块替换。关闭开关则把设置改回原值，Remote-SSH 便重新按自带方式安装。

接管脚本由扩展按主机生成在扩展的全局存储目录，职责拆成三个文件：

| 文件 | 内容 | 是否参与授权哈希 |
| --- | --- | --- |
| `接管安装-<主机>.ps1` | 薄脚本：只有主机名与一行调用，逐字节稳定 | **是**（内容变化会重新弹窗） |
| `接管安装实现.ps1` | 全部实际逻辑，从扩展目录原样复制 | 否 |
| `接管安装配置.json` | 模块路径、发布通道、各主机接管前的原 preconnect 脚本 | 否 |

薄脚本靠 `$PSScriptRoot` 找同目录的实现文件，所以扩展升级换目录也不会改变薄脚本内容；而逻辑与路径信息都放在后两个文件里，**日后改进逻辑无需重新确认授权**。接管前已有的 preconnect 脚本记在配置里，安装完成后由实现脚本直接调用（不套一层 `powershell`），其输出、异常与非零退出都如实汇入本次接管结果。

# 注意事项

- 还原的是「安装方式」：Remote-SSH 恢复自带安装；已由本模块装好的服务端原样保留（与自带安装产物同构，无需重装）。
- 接管期间请不要手动改写 `remote.SSH.preconnect`，该设置由本扩展管理；关闭开关时会整体恢复为接管前的取值。
- 免密登录（密钥认证）是接管的**硬性前提**：preconnect 的标准输入是 `ignore`，需要交互输密码的主机根本无法静默安装。接管脚本探测不到免密登录时会**直接报错并以非零退出码中止本次连接**，不会静默退回 Remote-SSH 自带安装——让「这台主机没配密钥认证」立刻暴露，而不是被掩盖成一次缓慢的自带安装。请为该主机配置密钥认证，或关闭开关改用自带安装。
- VS Code 更新到新提交号后的首次连接同样由本模块安装对应版本，无需手动干预。但旧 glibc 主机上的**原生模块补丁**（`*.node`）需要用 server 自带的 `node` 做加载验证，而 `node` 要等 Remote-SSH 首次连接时才打上 sysroot 补丁：故新提交号**首次连接后的原生模块补丁会延后到下一次接管完成**（本模块绝不去改 `node` 本身，实测把它补丁可能导致段错误而无法连接）。
